2. OBJETIVO DE LA VERSIÓN
======================================================================

Mejorar significativamente la experiencia móvil y acercar el CRM Android
al CRM de la plataforma web, manteniendo la misma fuente de datos Chatwoot.

La interfaz adopta la identidad visual:
- Azul principal: #13287E
- Amarillo de acción/acento: #FFF323

El diseño se inspira en aplicaciones modernas de delivery/servicios de
Colombia: jerarquía visual fuerte, tarjetas amplias, acciones grandes,
esquinas redondeadas, navegación inferior y alta legibilidad. No intenta
copiar una interfaz externa de forma literal.

======================================================================
3. CAMBIOS FUNCIONALES
======================================================================

CRM:
- Lista de conversaciones rediseñada.
- Avatar del contacto.
- Nombre, último mensaje, cantidad no leída y hora/fecha del último mensaje.
- Cabecera de chat más cercana al CRM web.
- Hora visible debajo de cada mensaje.
- Mensajes propios en azul #13287E.
- Mensajes entrantes en superficie blanca.
- Botón Analizar conservado.
- Botón Crear servicio aparece después de una extracción IA válida.

RENDIMIENTO DEL CHAT:
- Nuevo ChatCache persistente en cacheDir del dispositivo.
- La lista del CRM se muestra desde caché antes de terminar la llamada a Chatwoot.
- Al abrir una conversación se muestran primero los mensajes almacenados.
- Luego se sincroniza silenciosamente con Chatwoot.
- Envío optimista: el mensaje aparece inmediatamente en pantalla y luego se
  confirma con el servidor.
- Si el envío falla, el mensaje optimista se elimina y se informa el error.
- Chatwoot sigue siendo la fuente de verdad; el caché Android es descartable.

SERVICIOS:
- Continúa permitiendo crear servicios.
- Se agrega edición completa desde Android para role=admin.
- El detalle del servicio muestra botón Editar para administrador.
- Se pueden cambiar cliente, teléfono, dirección, ciudad, descripción,
  valor, colaborador, fecha, horario y notas.
- Se mantiene control de conflicto de colaborador/horario.
- Si cambia el colaborador, el servicio vuelve a assigned_unconfirmed.
- La edición se registra en appointment_history.

USUARIO:
- Nuevo endpoint /?action=me para recuperar el rol de una sesión móvil ya
  existente, permitiendo saber que el usuario es admin aunque la app se haya
  reabierto sin volver a iniciar sesión.

9. CAMBIOS DE BACKEND MÓVIL
======================================================================

Nuevos endpoints:
GET  mobile_api.php?action=me
POST mobile_api.php?action=appointment_update

crm_messages ahora entrega un contexto móvil enriquecido con:
- name
- phone
- avatar / avatar_url
- datos del cliente encontrado
- últimos servicios del cliente

appointment_update:
- exclusivo para admin;
- valida colaborador activo;
- valida datos requeridos;
- evita colisión de horario;
- reutiliza/actualiza cliente por teléfono;
- mantiene estado si no cambia colaborador;
- cambia a assigned_unconfirmed si cambia colaborador;
- registra appointment_history.

11. SEGURIDAD
======================================================================

- Los tokens siguen almacenándose como hash SHA-256 en MySQL.
- El token real sigue cifrado por Android Keystore.
- El caché de chat está en cacheDir, no en almacenamiento público.
- El caché se elimina al cerrar sesión.
- La edición de servicios se valida también en servidor como role=admin;
  ocultar el botón en Android no es el control de seguridad principal.
